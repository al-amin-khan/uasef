# Project Inception

## When to use
Initiate any new software idea through INIT-001 to INIT-016 with researched and approved documents.

## Preconditions
- Read the target repository's `AGENTS.md` and `.uasef/policies/`.
- Inspect the assigned task, known approved project artifacts, and actual repository state.
- Do not mistake a request for research for approval to implement or deploy.

## Method
Intake the raw idea verbatim; inspect known constraints; use the workflow manifest for task IDs and required outputs. Run progressive discovery, evidence-backed research, product definition, solution/UX/architecture, delivery planning and readiness gates. Ask targeted high-impact questions only. Do not pick a stack before problem discovery. Review task dependencies with `uasef next`; only a human records required approvals.

## Expected artifacts
`docs/00-inception/idea-brief.md, docs/00-inception/readiness-review.md`. Reference actual files and persistent task IDs. If a relevant artifact is not yet required, explicitly mark it deferred instead of inventing completeness.

## Deliverable format
1. Confirmed facts and supporting source/evidence (with dates where relevant).
2. Open questions and assumptions, each labeled as such.
3. Alternatives and recommendation with trade-offs.
4. Artifacts changed and requirement/task IDs.
5. Actual verification conducted, or precise reason not conducted.
6. Risks, approvals required, and next handoff.

## Non-negotiable guardrails
Never fabricate research, package compatibility, tests, deployment, approvals, or user validation. Request human review for sensitive/destructive/production changes. Prefer narrowly scoped action and record decisions in project artifacts.

## Additional guidance
Read [the task reference](references/inception-interview.md) when the decision needs more detailed evaluation.
